# 기본 디플로메시

현재 진입점은 `src/game/main.eps`입니다. FranceDp 주둔군과 koreaDp 스타일 시작 UI를 사용합니다.

| 모듈 | 기능 |
|---|---|
| `cities.eps` | 도시 소유권, 주둔군 생성·회수, 점령, 도시 수 캐시 |
| `income.eps` | 도시 세금과 수도·대도시의 주기 수입 지급 |
| `commander.eps` | MSQC로 동기화한 F+좌·우클릭 전군 명령 |
| `start_ui.eps` | 오프닝, 방장 빠른/세부 설정, 채팅 거점 선택, 게임 시작 |
| `rules.eps` | 개인전 동맹 규칙, 대기열/랜덤 팀 구성, 팀 동맹과 시야 |
| `unit_dat.eps` | `TrgUnit`/`Weapon` 문법의 파일런·주둔군 외형, 스탯, 공격 AI |
| `unit_orders.eps` | CUnit 직접 이동(6)·어택땅(14) 명령. 영웅별 UnitGroup에서도 재사용 |
| `army_groups.py` | 플레이어별 기본 부대와 영웅 UnitGroup의 컴파일 타임 등록 목록 |
| `debug.eps` | 동기화 채팅으로 유닛 생성·자원 설정·세금/주둔군/시작 타이머 변경 |
| `player_settings.eps` | 유닛·미니맵 플레이어 색상 설정. P8은 검정(40) |
| `unit_data.py` | UnitModel 키로 구분한 기본 5병종의 전투·외형·속성 JSON 적용 |

디버그 명령과 설정은 `doc/DEBUG.md`를 참고합니다. `debug_enabled`로 켜고 끕니다.

## 초기 맵 설정

`maps/base.scx`에 P1–P7 사람, P8 컴퓨터, P1–P8 테란 설정을 직접 저장합니다.
게임 초기화에서 `SetColor(P8, BLACK)`을 적용하며 빌드 레시피에서 `eudTurbo`를 사용합니다.
P1–P7 시작 위치와 공용 엔진 로케이션을 원본에 저장하며 도시 마커 260개는 비콘 그대로 남깁니다.
게임에 진입한 뒤 `onPluginStart()`에서 `unitDat.init()` → `unitData.init()` → `cities.init()` 순서로 실행합니다.
외형·공격 AI·버튼 제거 설정이 끝난 뒤 비콘을 지우고 같은 위치에 파일런을 생성해 무적으로 설정합니다.
변환은 빌드 단계에서 하지 않으며, 도시 소유권은 방어 병력의 전투 결과로 바뀝니다.
빌드는 입력 SCX의 설정을 사용하며 도시 데이터 JSON이나 맵 설정 플러그인은 사용하지 않습니다.

도시별 고정 로케이션 230개는 삭제했습니다. `map_data.py`의 `class Loc`에서 맵 이름으로
`EncodeLocation`을 선언합니다. 1–4는 주둔군·점령·점·비콘 변환, 5–11은 마우스,
12–18은 시작 위치, 19는 명령, 20은 MSQC, 21은 설정 화면용 `settings_view`, 64는 Anywhere입니다. 나머지 233슬롯은 비어 있습니다.
`Loc.city_capture`는 원본 맵에 320×320 크기로 저장합니다. 도시 좌표로 `Loc.city_point`를 옮긴 뒤
P9의 Map Revealer를 대상으로 `MoveLocation`을 실행합니다. 해당 유닛이 없으므로 점의 중심으로 이동합니다.
시작 도시 지급은 선택한 시작 위치 영역에서 처리하며, 개별 도시 판정은 저장한 CUnit과 공용 영역을 사용합니다.

## 시작 UI

koreaDp의 오프닝 → 방장 설정 → 국가 선택 흐름을 신규 맵의 거점 선택에 맞췄습니다.
오프닝·빠른 설정·세부 설정·동맹·팀 구성 단계는 매 틱 왼쪽 상단에 화면을 고정합니다.
거점 선택 단계부터 고정을 해제하고 선택 거점을 보여 줍니다.
120틱 오프닝 뒤 방장(참가자 중 가장 낮은 슬롯)이 빠른 설정을 선택합니다.

- 1: 개인전·선택·시야만
- 2: 개인전·랜덤·시야만
- 3: 팀전·선택
- 4: 팀전·랜덤
- 0: 세부 설정

빠른 설정은 ↑↓ 이동, → 또는 Y로도 확정합니다. 세부 설정은 ↑↓ 항목 이동, ←→ 변경이며
게임 종류·거점 선택 방식·개인전 동맹 허용 여부를 정합니다. 팀전은 대기열 또는 랜덤으로 팀을 나눕니다.
개인전의 동맹 설정은 가능/시야만/불가능을 지원하며, 시야만에서는 공격 동맹을 막고 공유 시야 선택을 허용합니다.
팀전은 같은 팀 동맹과 공유 시야를 유지합니다.
현재 구현하지 않은 경험치 배율·팀전2 팩션·조장 지명 메뉴는 표시하지 않습니다.

거점 선택에서는 채팅으로 스트라스부르·울름·아우크스부르크·뮌헨·뉘른베르크·레겐스부르크·잘츠부르크 또는 `랜덤`을 입력합니다. 숫자 1~7과 기존 `거점1`~`거점7`도 지원합니다.
중복 선택을 막으며, 개인전은 동시에 선택하고 팀전은 양 팀이 번갈아 선택합니다.
600틱 동안 선택하지 않으면 남은 거점을 무작위 배정합니다. 모두 선택하면 120틱 뒤 시작합니다.
로컬 채팅은 `chatEvent` → MSQC → 플레이어별 수신 배열로 동기화한 후 적용합니다.
P1–P7 참가자는 P8 컴퓨터의 시야를 공유하며 게임 시작 후에도 공유를 유지합니다.
각 참가자는 선택한 거점의 도시와 경보병 8기, 미네랄 1000을 받습니다. 인컴과 대도시 건설·승계 규칙은 INCOME.md를 참고합니다.
혼자 실행할 때는 개인전 선택/랜덤으로 시작합니다. 팀전은 2명 이상이어야 합니다.
도시가 2·3개인 거점은 해당 파일런 수만큼 도시로 계산합니다.

## 주둔군과 점령

파일런이 FranceDp와 같은 Tower Attack(명령 19) 상태가 되면
도시 파일런당 Broodling 6기를 생성하고 도시 HP를 30%로 낮춥니다.
주둔군은 파일런 기준 (-32,+32)부터 16픽셀씩 옮기며 생성하고, 지상·정지 상태로 고정합니다.
Broodling은 마린 외형·초상화·음성, 정지 공격 AI를 사용하는 주둔군입니다.
주둔군 1기당 HP 1800, 일반 공격력 75, 사거리 256, 인지거리 8타일(256픽셀), 공격 간격 24프레임입니다.
기본 방어력 9와 전용 Unused60 업그레이드를 사용하여 P1~P7은 19, P8은 9입니다.
공격 업그레이드 보너스는 0이며 기본 병종의 방어 업그레이드에는 영향을 주지 않습니다.
도시·주둔군 DAT는 파일런과 브루들링 및 전용 무기 117/119를 수정합니다. 기본 병종은 별도 JSON 설정을 사용합니다.
260개 도시 전체에 상시 주둔군을 깔지 않고 전투가 생긴 거점에만 생성합니다.

주둔군을 포함한 도시 소유자의 Men이 사라지면 FranceDp처럼 `CommandMostAt`으로
주변 병력이 가장 많은 플레이어에게 거점의 파일런을 넘깁니다. 동률은 원본처럼 낮은 슬롯 우선입니다.
파일런은 `Loc.city_point`에서 `GiveUnits(1, ...)`로 넘깁니다. `Loc.city_capture` 범위에서는
같은 소유자의 게이트웨이(`UnitModel.barracks`)를 `GiveUnits(All, ...)`로 함께 넘깁니다.
주변 포지의 양도는 아직 추가하지 않습니다.
점령 시 HP·쉴드를 100% 복구합니다. 공격 상태가 끊긴 뒤 400틱이 지나면 주둔군을 회수하고 HP를 복구합니다.
HP는 직접 대입하지 않고 저장한 CUnit 중심의 점 로케이션에서 `ModifyUnitHitPoints(1, ...)`로 변경합니다.
사용자 설명에 따라 불꽃·이미지 처리를 엔진에 맡겨 직접 HP 대입으로 인한 게임 종료를 피합니다.
쉴드 복구도 `ModifyUnitShields`로 처리합니다. DAT의 최대 HP 설정은 이 인게임 HP 변경과 별개입니다.
퇴장한 사람의 도시는 P8로 되돌립니다.
도시 CUnit은 생성 직후 `EUDVArray(cfg.CITY_COUNT, CUnit)()`에 저장합니다.
매 틱 저장된 도시 260개를 모두 직접 검사하며, 전체 유닛 순회나 좌표를 통한 도시 번호 역검색은 하지 않습니다.
파일런 하나마다 독립적으로 전투 타이머·주둔군·점령을 처리합니다.
주둔군도 생성한 CUnit과 세대 번호를 저장해 해당 도시의 살아 있는 주둔군만 회수합니다.
점령은 `CUnit.cgive()`로 해당 파일런만 이전하고 세금 도시 수를 즉시 갱신합니다.

## 세금과 전군 명령

720틱마다 원본 거점의 소유 도시 하나당 20미네랄을 지급합니다.
새로 건설한 파일런은 세금 도시 수에 포함되지 않습니다.
F를 누른 상태로 우클릭하면 전군 이동, 좌클릭하면 전군 공격입니다.
일꾼·주둔군·건물은 전군 명령에서 제외하고, 전투 유닛 및 수송·지원 유닛에 적용합니다.
MSQC가 마우스 위치와 입력을 동기화하므로 로컬 입력을 직접 게임 상태에 적용하지 않습니다.
전투 유닛은 `EUDLoopNewUnit()`에서 소유 플레이어의 기본 UnitGroup에 등록합니다.
플레이어별 기본 부대 및 등록된 모든 영웅 그룹은 각각 매 틱 `UnitGroup.cploop`을 한 번씩 순회합니다.
`Order()` 트리거나 factories 그룹은 사용하지 않습니다. 마우스 로케이션 중심을 플레이어당 한 번 읽고,
`unit_orders.issue`가 저장된 CUnit의 목표 좌표·명령 상태·명령 ID를 직접 설정합니다.
`UnitGroup`은 명령이 없는 틱에도 `entry.dying`으로 죽은 항목을 제거합니다.
이후 영웅별 부대에서도 각 그룹의 CUnit을 같은 `issue` 함수에 넘기면 됩니다.

영웅 모듈에서는 컴파일 타임에 `army_groups.register_hero_group(player, group)`으로 그룹을 등록합니다.
등록은 모듈 import 때 수행하며, EPScript 런타임 호출 함수가 아닙니다.
전군 명령은 이 플레이어의 기본 부대와 등록된 모든 영웅 그룹에 적용됩니다.
실제 영웅과 부대 편성 기능은 아직 없으므로 향후 등록 대상 선정 코드를 함께 추가해야 합니다.
유닛을 기본 부대와 영웅 부대에 중복 등록하면 안 됩니다.
Python 런타임 등록 함수는 `f_add_default`, EPScript 호출은 `groups.add_default(epd)`입니다.

수치는 `src/data/diplomacy.json`에서 수정합니다. 주기는 트리거 틱이며 실제 시간은 게임 속도에 따라 달라집니다.
파일런·주둔군의 DAT는 `src/game/modules/unit_dat.eps`에서 직접 편집합니다. 예:

```eps
TrgUnit(156).maxHp = 2000 * 256;
TrgUnit(40).flingy = 78; // 마린 외형
Weapon(119).damage = 80;
```

특수유닛과 나머지 일반 유닛 스탯 변경은 아직 적용하지 않았습니다.
FranceDp의 TBL·RequireData 스냅샷도 기본 비활성 상태입니다.

## 검증

euddraft 실제 빌드 및 freeze 처리를 확인했습니다. 맵 설정 테스트는 7개 사람 슬롯과 시작 위치,
260개 비콘 유지, 도시 로케이션 간 다른 도시가 섞이지 않는지 검사합니다.
`python -m unittest discover -s tests -v`로 실행합니다.
인게임과 여러 사람이 참여하는 멀티플레이 검증은 별도로 필요합니다.
