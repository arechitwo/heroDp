# 군영 자동 생산

군영은 UnitModel.army_camp(Protoss Robotics Facility)다. FranceDp와 DPaper의 대기열 반복 생산 구조를 참고한다. 플레이어별 군영 그룹 대신 하나의 CAMPS UnitGroup을 빌드 때 선언하고 trackNewUnits에서 신규 군영을 등록한다. 매 틱 entry.dying으로 죽은 항목을 정리한다.

| 버튼 위치 | 기능 |
|---|---|
| 1 / Q | 창병 등록: 생산 시 100금 |
| 2 / W | 경보병 등록: 생산 시 120금 |
| 3 / E | 장궁병 등록: 생산 시 160금 |
| 7 / I | 자동 훈련 안내. 군영 버튼셋을 그대로 표시하며 게임 명령은 내리지 않음 |
| 8 / R | 랠리 지정 |
| 9 / Esc | 마지막 등록 항목 제거 |

기본 대기열 다섯 칸을 훈련 목록으로 사용한다. 같은 병종을 중복 등록할 수 있으며 매 생산 주기에 각 등록 항목당 1기씩 반복 생산한다. 자동 생산 후 목록을 비우거나 생산 항목을 회전시키지 않는다. 다섯 칸 검사는 py_range로 빌드 때 펼치며 임시 배열은 만들지 않는다. 큐의 유닛 ID는 WORD 전체를 읽지 않고 epdswitch의 해당 바이트 마스크로 검사한다.

등록 비용은 0이다. 실제 생산 비용은 resource/units/properties.json의 recruitment.cost에서 읽는다. 세 병종의 production.minerals는 0, production.time은 720이다. 기존 RequireData의 종료 명령 프로그램에 연결하여 다른 건물의 유닛 생산 조건이 등록을 막지 않게 한다. 건설·유닛 생산 설명 TBL은 단축키 다음에 0x01 한정자를 사용한다. 등록 버튼 설명에는 주기당 실제 비용을 적는다.

src/data/diplomacy.json의 army_period_frames가 생산 주기이며 초기값은 720프레임이다. 약 24프레임/초에서 30초에 해당한다. 세금 지급 뒤 생산을 처리한다. 완성되고 전원이 들어온 군영만 자동 생산한다. 군영마다 현재 소유자를 읽어 그 플레이어의 자원을 확인하고 생성에 성공한 뒤 비용을 차감한다. 자원이 부족하거나 유닛 슬롯이 없으면 해당 항목은 건너뛴다. 목록은 유지한다. 현재 P1~P7 소유 군영만 자동 생산한다.

네이티브 엔진이 훈련 목록 첫 항목을 실제 완성하지 않도록 군영의 currentBuildUnit(0xEC) 포인터가 있을 때 그 유닛의 remainingBuildTime을 조정한다. produce=1인 주기에는 군영에서 등록 가능한 세 병종의 production.time 중 최솟값(현재 720)으로 되돌려 게이지를 다시 진행시킨다. 이 최솟값은 빌드 때 계산한다. 나머지 틱에는 10 미만일 때만 10으로 보정한다. 매 틱 최댓값으로 고정하지 않으며 군영 자체의 건설 시간은 건드리지 않는다.

병력은 군영 위치의 생성 로케이션에서 CreateUnit으로 생성한다. 랠리 위치는 0xF8에서 0x1FFF1FFF 마스크로 읽고 modules.unit_orders.issue를 통해 목표 좌표·명령 상태를 설정하며 orderID 14로 공격 이동한다. 랠리가 0이면 군영 좌표를 사용한다. 생성된 병력은 다음 신규 유닛 순회에서 기존 기본 부대에 등록된다.

도시 점령 시 Loc.city_capture 안의 군영도 병법원과 함께 Give한다. 별도 플레이어별 군영 그룹 이동은 없으며 다음 생산 때 새 소유자가 비용을 내고 병력을 받는다. 기본 TBL 773·776의 생산 상태 표시는 <훈련 목록>으로 바꾼다.

군영 건설비와 슬롯 확장·생산 가속 업그레이드는 아직 추가하지 않았다. 이번 변경은 빌드·테스트·별도 코드 검증을 실행하지 않았다.
