# 인컴과 대도시

설정은 src/data/diplomacy.json에서 관리한다. 게임 시작 후부터 타이머가 진행되며, 시작 설정 화면에서는 수입이 발생하지 않는다. 아래 초 단위는 24프레임을 기준으로 한 설계상 표현이다.

| 항목 | 값 |
|---|---:|
| 시작 자금 | 1000금 |
| 일반 도시 세금 | 720프레임마다 도시당 100금 |
| 수도 기본 수입 | 24프레임마다 5금, 세력당 한 번 |
| 대도시 추가 수입 | 완성된 대도시당 24프레임마다 5금 |
| 대도시 건설비 | 600금 |
| 대도시 건설 시간 | 720프레임 |
| 대도시 한도 | max(1, 일반 도시 수 / 3의 정수 몫) |

대도시 한도는 엔진 전체 유닛 수 테이블 0x582324를 사용한다. 완성·건설 중인 건물과 수도로 승계한 대도시를 포함하며 대리 프로브 예약은 별도로 세지 않는다. 건설 중 수만 필요하면 전체 수에서 완성 수 테이블 0x584DE4의 값을 빼면 된다. [BWAPI의 미완성 수 계산](https://github.com/bwapi/bwapi/blob/main/bwapi/BWAPILIB/Source/Player.cpp)도 전체 수에서 완성 수를 빼는 방식이다.

빠른 연속 건설로 한도를 넘긴 경우 commander.trackNewUnits에서 신규 미완성 대도시 중 초과분만 제거하고 건설비 600금을 전액 반환한다. 같은 순회 중 제거로 엔진 카운터가 갱신되는 시점에 영향을 받지 않도록 첫 신규 건물에서 플레이어별 초과 수를 한 번 계산하고 제거할 때 차감한다. 이 값은 매 순회 초기화하며 건설 예약 상태가 아니다. 영토를 잃어 한도를 넘겨도 기존 건물은 유지한다. 일반 건설비 차감과 정상 건설 취소 환불은 엔진에 맡기며 별도의 자원 중복 차감은 없다.

대도시는 완공된 뒤에만 추가 수입을 준다. 대도시 자체는 일반 도시 세금 계산에 넣지 않는다. 수도가 없어져도 다른 완성 대도시의 추가 수입은 유지한다.

수도가 파괴되면 등록된 대도시 UnitGroup에서 먼저 확인된 완성 대도시를 선택한다. 건설 중인 대도시는 제외한다. 해당 건물을 제거하고 그 위치에 수도 유닛을 생성해 기존 수도 EPD·세대·활성 상태에 등록한다. 승계된 수도는 기본 수입 5금과 대도시 추가 수입 5금을 함께 제공하며 대도시 한도도 한 자리를 계속 사용한다. 이 수도가 다시 파괴되면 해당 추가 수입과 한도 사용이 사라진다. 완성 대도시가 없으면 기존 일반 도시의 수도 소환 방식을 사용한다.

대도시는 기존 신규 유닛 순회에서 한 번만 등록한다. 매 틱 UnitGroup의 죽은 항목을 정리하고 완성된 건물 수와 수도 후보를 갱신한다. 세력별 전체 유닛 재검색은 하지 않는다. 기본 세금은 기존 도시 수 캐시를 사용한다.

## 구매력

수도를 보유하고 대도시가 없을 때 720프레임 총수입은 도시 1개 250금, 3개 450금, 5개 650금, 10개 1150금이다. 대도시 한 개가 추가되면 같은 기간 150금을 더 받는다.

대도시 투자금은 완공 후 2880프레임, 착공 후 3600프레임에 회수한다. 각각 약 120초와 150초에 해당한다. 시작 병력은 기존 경보병 8기를 유지한다. 군영 생산 시스템과 군영 건설비는 이번 인컴 구현 범위에 포함하지 않는다.

이번 변경은 사용자 지침에 따라 빌드·테스트·별도 코드 검증을 실행하지 않았다.
