# 영웅 설계 초안

구현은 보류하고 기본 게임 루프와 병종·건물 기능을 먼저 완성한다. 아래 인물·능력·수치는 확정 데이터가 아닌 논의 초안이다.

## 영주·영웅 기반 구조 작업 분리

이후 기반 구조 구현은 PR #5의 브랜치 feature/unit-roster-cleanup을 베이스로 하는 별도 초안 PR에서 진행한다. PR #5의 리뷰·머지 후 새 PR의 베이스를 main으로 변경하여 영웅 관련 변경만 리뷰한다. 이 문서 갱신 시점에는 게임 코드 구현을 시작하지 않았다.

- 플레이어마다 영주를 포함한 영웅 4슬롯을 둔다. 첫 슬롯은 구이 몬태그 영주, 나머지 3슬롯은 추가 영웅이다. 영주 7명과 추가 영웅 21명으로 전체 실체 슬롯은 28개다.
- 영웅 생성 시 CUnit과 해당 영웅의 스킬 처리 함수를 슬롯에 연결한다. EUDFunc 계열의 함수 포인터 저장·호출 API를 확인한 뒤 적용한다.
- UnitGroup은 런타임 함수 인자로 전달하지 않는다. 부대 그룹은 빌드 때 선언·연결한다.
- 그룹을 여러 번 순회하지 않도록 기존 순회 안에서 실행할 유닛별 처리 콜백을 함수 포인터로 전달하는 구조를 검토한다. 명령 여부와 무관하게 매 틱 dying 항목을 정리한다.
- 스킬의 지점형·유닛 대상형·자기 강화형을 공통 명령으로 받아, 영웅별 함수에서 목표 좌표·ptr·자기 자신으로 해석한다.
- 빌드와 테스트는 별도 요청이 있을 때만 실행한다.

## 슬롯과 등장 제한

- 공통 영주 구이 몬태그는 별도다.
- 추가 영웅은 P1~P7 각각 3슬롯, 동시에 최대 21명이다. 슬롯 번호는 클래스와 무관하며 전사·궁수·법사 어느 영웅이나 배정할 수 있다.
- 초기 명단은 전사·궁수·법사 각 4명, 총 12명이다. 세력 간 같은 영웅의 중복 등장은 허용한다.
- 같은 세력 내 동일 영웅 금지와 동일 클래스 최대 2명은 제안 단계이며 아직 확정하지 않았다. 사망 후 추첨 복귀 규칙도 후속 확정한다.
- 장기적으로 영웅 데이터 100~200종을 준비하고 21개 실체 슬롯을 재사용하는 구조를 목표로 한다.

## 버튼과 마나

- 7번: 소속 UnitGroup 부대 공격(지점 지정, 어택땅 14).
- 8번: 소속 UnitGroup 부대 이동(지점 지정, 이동 6).
- 9번: 영웅 고유 능력. 패시브 설명 / 즉발 / 지점 지정 / 유닛 대상 중 하나다.
- 빌드 때 영웅별 버튼 템플릿을 만들고, 영웅 배정 시 전용 슬롯의 버튼셋 연결을 교체한다. 공유 템플릿 자체를 런타임에 덮어쓰지 않는다.
- 슬롯 배정 때 Spellcaster 속성·현재 마나·버튼을 함께 설정한다. 실제 네이티브 마법 사용 조건과 선택 화면 갱신은 구현 전에 확인해야 한다.
- 소스 검토상 버튼셋과 마나 속성 변경은 가능하지만 인게임 검증은 아직 하지 않았다. 네이티브 최대 마나는 일반 200/영웅 속성 250 등의 별도 규칙을 따른다.
